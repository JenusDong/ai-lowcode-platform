## 三、遇到的问题与解决方案

### 问题 1：组件在面板中显示，但拖拽后显示 "component not found"

**原因**：缺少 UMD 文件和 Meta 文件

**解决方案**：
- 创建了 `mall-components.umd.js` 文件
- 创建了 `mall-components-meta.js` 文件
- 确保文件正确暴露全局变量

**经验总结**：
- UMD 文件和 Meta 文件是组件注册的关键步骤
- 必须正确暴露全局变量
- library 名称必须与 UMD 文件中的全局变量名一致

### 问题 2：组件库面板显示空白，无法选择组件

**原因**：assets.json 中存在重复的包定义

**解决方案**：
- 删除了重复的 `echarts-component` 包定义
- 确保每个包只定义一次
- 检查 JSON 格式正确

**经验总结**：
- assets.json 配置必须准确无误
- 避免重复的包定义
- 使用 JSON 验证工具检查配置

### 问题 3：组件渲染异常，无法读取 `SearchOutlined`

**原因**：UMD 环境中无法正确访问 Ant Design 图标

**解决方案**：
- 移除了搜索框前的图标
- 避免在 UMD 环境中使用 `antd.Icon`

**经验总结**：
- UMD 环境中需要特别注意外部依赖的使用
- Ant Design 图标需要单独从 `@ant-design/icons` 引入
- 或者完全避免使用图标，改用文本或其他方式

### 问题 4：组件渲染异常，无法读取 `pageSize`

**原因**：useState 使用方式错误

**解决方案**：
- 为每个状态值单独使用 `useState`
- 正确理解 `useState` 返回的数组结构

**经验总结**：
- `useState` 返回数组，第一个元素是状态值，第二个元素是更新函数
- 不能解构多个值
- 每个状态应该单独管理

## 四、技术方案评估

### 优势

#### 1. 灵活性
- 组件支持细粒度的区域配置
- 数据源适配层设计灵活
- 可以适应不同的业务场景

#### 2. 可配置性
- 通过 LowCodeEngine 的属性面板即可配置
- 提供直观的开关和数组配置
- 支持多种预设模板

#### 3. 复用性
- 一个组件可以适应多种业务场景
- 减少重复开发工作
- 类型定义可以复用

#### 4. 可维护性
- 清晰的代码结构
- 易于扩展新的配置项
- 完善的文档

### 不足

#### 1. UMD 文件维护成本高
- 需要手动维护 UMD 文件
- 代码重复（源代码和 UMD 文件）
- 容易出现不一致

#### 2. 图标使用受限
- UMD 环境中无法直接使用 Ant Design 图标
- 需要额外的处理或避免使用

#### 3. 调试困难
- UMD 文件中的错误难以定位
- 需要在浏览器中调试
